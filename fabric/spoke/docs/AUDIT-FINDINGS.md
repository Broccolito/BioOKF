## 2. Prioritized triage (top items across all components)

1. **[CRITICAL] MCP-M1** — unauthenticated world-reachable Studio control socket → arbitrary local code execution.
2. **[HIGH] MCP-M2 / M3** — MCP `read_page`/`write_page` arbitrary file read/overwrite (no canonicalize/symlink guard).
3. **[HIGH] FABRIC-F1** — `spoke-fabric query` runs arbitrary Cypher incl. **writes/DDL** on a superuser connection (lost the old spoke-cli read-only guard).
4. **[MED] FABRIC-F2/F3** — fabric connects as default `neo4j` superuser + fully inlines values into Cypher (no query params).
5. **[MED] CLI-C1 = FABRIC-F5** — `bokf export` `edge_count` excludes synthesized edges; the fabric's own validate gate rejects a raw export. Two tools disagree; three code paths report three edge totals.
6. **[MED] CLI-C2** — `bokf restore <sha>` destructive, unvalidated tree checkout.
7. **[MED] CLI-C3** — `export` silently drops unparseable/duplicate nodes (GUI shows a clean-looking payload).
8. **[MED] MCP-M5/M6** — `bokf_convert` SSRF; any path registerable as a base.

## 3. spoke-fabric (the mapping harness)

**F1 · `query` subcommand has no read-only guard — can write/delete on a superuser connection. [HIGH]**
`src/main.rs:106` — `Commands::Query` runs any Cypher via `graph.execute()`. The original `spoke-cli`
rejected write/DDL keywords; the native fabric dropped that. Combined with F2, `spoke-fabric query
"MATCH (n) DETACH DELETE n"` would delete SPOKE data. The `cypher_str` guard-word *splitting* only
protects string literals during escaping — it does **not** block a top-level write clause.
*Fix ideas:* reject queries whose clauses include CREATE/MERGE/DELETE/SET/REMOVE/DROP, or open a
read-only session/route, or connect with a read-only user.

**F2 · Connects as the default `neo4j` superuser. [MED]**
`.env` uses `KNOWLEDGE_GRAPH_USERNAME=neo4j` (`SHOW CURRENT USER` returns `roles: null` — Community
Edition, no RBAC = full write). A read-only mapping task should use a least-privilege read-only role;
today any write bug (F1/F3) is write-capable against production SPOKE.

**F3 · All Cypher is string-inlined; no neo4rs query parameters. [MED]**
`src/client.rs` builds queries with `cypher_str`/`cypher_value`/`cypher_list`/`cypher_pairs`
(30 sites; **0** `.param()` calls). Escaping *holds* for adversarial names I tested
(`BRCA1' RETURN 1 //`, `x'}) RETURN 1 //`, backslashes, embedded quotes → clean `not_found`/`ambiguous`,
no injection). But inlining relies on `cypher_str` being perfectly correct forever; parameterized
queries (`.param("q", value)`) remove the class of risk. Defense-in-depth given F2.

**F4 · `link` path panics on a malformed export. [LOW-MED]**
The gated `pipeline` validates `graph.nodes/edges` before use, but `link` → `annotate_graph`
(`src/main.rs`) does `export["graph"]["nodes"].as_array_mut().unwrap()` with no shape check — a
hand-crafted/truncated export panics instead of erroring gracefully.

**F5 · Fabric rejects a raw `bokf export` (edge_count gate). [MED]** — same root as CLI-C1.
`validate_invariants` asserts declared `edge_count == graph.edges.len()`; `bokf export` declares a
count that *excludes* synthesized edges, so the pipeline **fails** on an unmodified export (I had to
normalize counts in the sweep). The two BioOKF tools have an incompatible edge_count contract.

**F6 · Disk cache never expires. [LOW-MED]**
`runs/.spoke_cache` stores query→rows keyed by cypher hash with **no TTL/invalidation** (confirmed:
no `mtime`/`expire`/`stale` logic in `client.rs`). If SPOKE is updated, re-runs silently return stale
mappings/ids. Consider a TTL, a version stamp, or `--no-cache` in CI.

**F7 · Deterministic recall is low for measurement/molecule-heavy KBs. [LOW]**
`09-misc-clinical` mapped only 16% deterministically; its unmapped nodes are Molecule (70),
Phenotype (44), BiomedicalMeasure (40). This is largely the hard-call *floor* (the sweep ran no LLM
tier); still, BiomedicalMeasure→ClinicalLab (LOINC) and Molecule→Compound/Protein are the weakest
crosswalk paths and benefit most from the LLM review tier + the protein-description recovery.

**F8 · Positive.** Ran 8,438 nodes across 12 domains with 0 panics; adversarial node names are
correctly escaped; all node types fell within the known 28 (no crosswalk type gaps).

*(Known precision items already reported from the ebv-ms systematic check — source-xref propagation,
fuzzy/derivative matches, protein description edge cases — several already fixed with the 5 guards.)*

## 4. bokf CLI + bokf-core

**C1 · `edge_count` inconsistency (three different edge totals). [MED]**
`bokf-core/src/export.rs:81` (and `:134`) sets `edge_count = edges.filter(!synthesized).count()` while
`graph.edges` (built at `graph.rs:126-150`) includes synthesized `reported_in` edges. `bokf stats`
counts only authored `n.edges` — a third total. Breaks strict validators (see F5). `cmd_export`
prints only `node_count`, so the mismatch is invisible from the CLI.

**C2 · `bokf restore <sha>` → unvalidated destructive tree checkout / arg-injection. [MED]**
`bokf-core/src/git.rs:195-204` passes `sha` verbatim to `git read-tree -u --reset` (overwrites +
deletes working tree). No check that `sha` is in this repo's history; any tree-ish (a tag, stash,
other branch) is accepted, and a `sha` starting with `-` is misparsed as an option (nothing prepends
`--`). An agent can be induced to blow away `knowledge/`.

**C3 · `export` silently drops unparseable / duplicate-identifier nodes. [MED]**
`bundle.rs:73-94` records `parse_errors`/`duplicate_identifiers` then continues; `export.rs:70-96`
never emits them (and `studio_*_doc` omits the `lint` block entirely). 30 of 100 files failing to
parse export as a clean `node_count: 70` with no signal. A duplicate id makes only the first node
reachable via `pages` while the graph still renders all — another count/content divergence.

**C4 · Export determinism is incidental, not contractual. [LOW]**
`serde_json` built without `preserve_order` (keys BTree-sorted), `files.sort()` gives node order, but
`graph.edges`/external-node synthesis order rests on iteration order with no terminal sort. Any future
iteration change silently breaks reproducibility. Recommend an explicit final sort of nodes/edges.

**C5 · No size/nesting bound on parsed markdown/YAML → OOM/DoS on a hostile bundle. [LOW]**
`bundle.rs:75` `read_to_string` (no cap) + `parse.rs:49` `yaml_to_json` recursion (no depth guard).
URL/zip ingestion is capped (50 MiB / 200 members) but the on-disk parse path is not.

**C6 · Registry TOCTOU + no path validation of registered bases. [LOW]**
`registry.rs:30-45` load→mutate→save has no cross-process lock (CLI/MCP/Studio share the file); two
concurrent `register`s lose an update. `path` is stored verbatim (no existence/`..` check) and
`resolve` hands it back trusted.

**C7 · Empty-string identifier accepted. [LOW]** `parse.rs` / `validate.rs` treat missing `type`/`id`
as fatal but accept `identifier: ""` → a node keyed on `""`. (Edge required-fields are enforced well.)

**C8 · Read-side path joins don't reject `..`/symlinks. [LOW]** `raw_source` (frontmatter) and
`lint.rs:198-203,521-533` / `export.rs:11-18` `bundle.root.join(untrusted)` with no confinement — a
crafted `raw_source: [../../etc/passwd]` makes lint stat / read outside the bundle. (Write paths are
safe — slug+hash derived.)

**C9 · `split_frontmatter` treats `...` as a terminator → silent body truncation. [LOW]** `parse.rs:36-46`.

**C10 · `repair_frontmatter` silently rewrites values on any YAML parse failure. [LOW]** `parse.rs:106-132`
— regex line-repair can turn a list/number into a quoted string with no diagnostic that repair ran.

*Overall CLI health:* well-structured, defensive for *careless* (not hostile) LLM authors; solid SSRF
guard on URL fetch, slug+hash-confined ingestion writes, atomic registry writes. Weakest against a
*hostile on-disk bundle* and strict downstream consumers.

## 5. bokf-mcp server + Studio backend

**M1 · [CRITICAL] Unauthenticated, world-reachable control socket → local RCE.**
`studio/src-tauri/src/main.rs:1495-1501` binds `/tmp/biookf-tauri-mcp.sock` with **no auth token**
whenever `BIOOKF_STUDIO_CONTROL` is set (which `bokf_studio_open` always does). The plugin only checks
a token if one is configured (`socket_server.rs:497`), and the socket sits in world-writable `/tmp`
with no `0600`. Any local process can connect and call `execute_js` → the Tauri `invoke` bridge → any
command incl. `install_update` (admin osascript) and `term_open` (a shell). *Repro:* `nc -U
/tmp/biookf-tauri-mcp.sock` then an `execute_js` frame. *Fix:* per-user `0700` socket dir or require an
auth token.

**M2 · [HIGH] `bokf_read_page` arbitrary file read.** `ops.rs:36-38,68-71` — `readable_path` = `bundle.join(safe_relative(page))`;
`safe_relative` only blocks absolute/`..` **strings** — no canonicalize, no allow-list, no symlink
check (unlike Studio's `get_node_file`, which requires `is_knowledge_markdown` + `safe_existing_bundle_path`
canonicalize-containment). A symlink inside a bundle pointing at `~/.ssh/id_rsa`, or `bundle=` set to
any dir, reads arbitrary files.

**M3 · [HIGH] `bokf_write_page` arbitrary file overwrite + validate-after-write.** `ops.rs:25-33,40-66`
— `writable_path` restricts the logical prefix + blocks `..` but never canonicalizes/checks symlinks;
`std::fs::rename` follows a symlink `knowledge/x.md → ~/.zshrc`. Also validates the doc **after** it's
already renamed into place → a bad write silently corrupts the node.

**M4 · [HIGH] `execute_js` string-interpolation design.** `main.rs:484-556` — safe *only* because every
site applies `json_str`; any future call site that forgets it (or interpolates a non-string) is a
webview injection. Inherently dangerous primitive, un-sandboxed.

**M5 · [MED] `bokf_convert` SSRF + update chain.** `main.rs:330-352` ingests arbitrary caller URLs (no
scheme/host allow-list); the Studio update path `curl -fL`s a release asset and runs it via an
admin-privileged osascript relauncher (codesign/spctl verified, but reachable from the M1 socket).

**M6 · [MED] Any path registerable/operable as a base.** `ops.rs:142-189` `scaffold` auto-registers +
sets-active globally; every `bundle:`-taking MCP tool accepts a raw path (no registry-membership
check), and `set_active` writes an arbitrary id to the shared pointer.

**M7 · [MED] Raw OS/git error strings leaked to clients** (paths, home dir, file-existence oracle) —
amplifies M2. **M8 · [LOW]** byte-slice panic latent in `restore_to` fallback. **M9 · [LOW]**
`sessions().lock().unwrap()` poisoning self-DoS. **M10 · [LOW]** `source_info` uses a second,
string-based traversal guard (inconsistent with the canonicalize path).

*Overall MCP posture:* the Studio's *own* file commands are well-defended (registry-gated +
`clean_bundle_rel` + allow-list + `canonicalize` containment). The **MCP `ops.rs` never got the same
treatment** (string-only checks), and the **unauthenticated control socket** widens the real trust
boundary to "any local process while the control channel is up." Top fixes: lock down the socket
(M1) and port the Studio's canonicalize+allow-list into `ops.rs` (M2/M3).
